# 时间与监控卡片自适应优化：开发流程

日期：2026-10-06；阶段：代码与针对性验证完成，标准 Debug 已启动，待用户实机验收。

## 1. 调研报告

### 时间卡片

当前卡片为 Glance。`GlanceWidgetContent.xaml` 的时间/日期文字引用主题画刷，`ApplyImageAwareTheme` 仅在存在图片时请求深色主题；没有分析文字所在区域的背景。宿主独立前景资源也参与最终画刷解析，因此仅切换 RequestedTheme 不能保证照片上的对比度。用户截图已证实暗色照片上出现暗色时间，但本轮尚未通过运行时资源探测区分具体画刷贡献。

`GlanceImagePaletteService` 已有 40 像素缩略取色与路径/写入时间缓存，但用于日历材质，以全图主色为依据。文字应按当前图片裁剪、焦点及文字覆盖区域取样，复用小样本与缓存方式，不能每秒解码全图。

纯互补色或 RGB 反色不保证亮度对比，例如中灰反色仍接近中灰。建议保留互补色倾向，同时调节明度；日期等普通文字以 4.5:1 为验证目标。复杂照片无法仅靠单一文字颜色满足每处像素对比，必要时在文字区域增加克制的遮罩；高对比度模式回退系统前景/背景。

Bing 已通过 `GlanceImageService` 接入，获取历史目录并下载缓存；当前 Glance 默认 30 分钟随机轮播，在线刷新还有会话完成标记。将间隔改成 1440 分钟并不能保证每天切到当天图片，也不能覆盖睡眠跨天与离线恢复。

2026-10-06 核对来源：

- [微软 Bing 首页说明](https://support.microsoft.com/en-us/bing/explore-the-homepage)：首页每日新图片。
- [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字 4.5:1，大字 3:1，色相差异不代替亮度对比。此处作为可读性校验依据，不声明本软件已获得无障碍认证。
- 项目设计基线 `docs/design/Design.md`、`docs/design/windows-native-baseline.md`；沿用原生字体、主题回退和共享外壳。

现有 Bing 图片目录属于已经接入的服务路径，本轮没有找到可据以承诺稳定性的公开 API 契约。沿用现有缓存、取消、网络策略和失败回退，保留来源及版权信息，不安装 Bing Wallpaper 后台软件。

### 监控卡片

`SystemMonitorWidgetContent` 使用固定的 14/12 DIP 字号、26 DIP 行高、10 DIP 外边距及固定分块间距，放在 ScrollViewer 中；窗口宽高由共享宿主分别保存，二者没有缩放约束，所以自由拉高会扩大背景空白。共享 `WidgetWindowBase.Interaction` 目前对所有普通卡片分别计算宽高。

监控内容固定创建 CPU/GPU 各五项、内存、显存、上传、下载、IP。`SystemMonitorOptions` 没有指标启用配置，采样器每轮读取所有来源。仅隐藏 UI 不能满足“选择不监控”的语义，需要同时避免不必要的读取；例如禁用 CPU 温度和功耗后，不应继续启动 CPU 传感器辅助采样。

工作区有先前未验收的采样缓存和生命周期优化，本轮保留，不撤销，不将其自动视为本轮已验收功能。

## 2. 问题澄清

已确认目标：时间在不同背景下清楚；时间卡片背景订阅 Bing，每日更新；监控背景、内容、字号和间距等比缩放；可关闭监控项，默认保留当前所有信息。

建议本轮口径：

- “背景壁纸”指截图中时间卡片内部背景，Windows 桌面壁纸不在本次范围。
- “每日轮播”采用每日最新可用 Bing 图片；当地日期跨天、启动和睡眠恢复时检查，未联网保留上一张成功缓存，网络恢复后限频重试。现有历史轮播和本地图片模式仍可选择。
- 时间/日期使用自动互补色加亮度校验；图片或裁剪改变时更新，时钟每秒走动不重复取色。
- 监控设置提供 CPU、GPU、内存、显存、网络分组及组内指标选择。全部默认开启，包括现在显示不可用的风扇；用户关闭后隐藏该项并跳过不需要的采样来源。可全关，全关时停止采样并保留设置入口和简短占位提示。
- 设置保存至各卡片现有配置；旧配置缺少新字段时沿用默认全部开启。当前时间卡片启用 Bing 每日模式，但保留原图片列表以便切回。

用户已回复“开始开发”，本轮按上述口径实施，无新增审批项。

## 3. 开发规划

1. **时间前景**：添加独立可测试的互补色/亮度计算策略，限制到时间和日期文字；复用缩略采样，覆盖图片裁剪、透明度和主题变化，异步结果核对当前图片，保留系统高对比度回退。既有日历与按钮配色不顺带重做。
2. **Bing 每日模式**：在 Glance 配置与设置页增加每日更新模式，复用现有服务/cache，选择最新可用图并按日期去重；不只靠固定 24 小时计时器。图片目录增加可选来源日期，旧缓存无此字段仍可读取，不能将下载时间当成壁纸发布日期。覆盖缓存先显示、启动/跨天/恢复检查、限频失败重试、停用/隐藏取消及旧模式兼容。可注入时间与图片目录以验证跨天，无需等到真实午夜。
3. **监控项**：添加默认兼容的指标启用策略与设置勾选；Render 仅访问已建立控件，关闭分组移除整个分块。按启用来源重建/释放 PDH、NVML、CPU bridge 和网络计数，切换后重新暖机，不复用陈旧速率/值。按所需功能共享读取，例如上传/下载共用同一网卡统计。
4. **等比缩放**：按已启用信息测量基准内容宽高；字体、图标、进度条、内边距及分块间距一起缩放。增加默认无作用的宿主几何约束，仅监控启用；拖边/拖角以对侧边缘或角为锚点，约束宽高比例和当前屏幕工作区，不裁切内容。关闭项目后收紧高度，避免保留旧空白。保留位置吸附、屏幕选择及胶囊模式；小尺寸受可读最小值限制，大尺寸受屏幕限制。
5. **验收与交付**：先验证纯颜色、日期调度、配置默认、采样启停及几何算法；按项目约定停止仓库实例、构建、启动标准 Debug。真实截图对照由实际操作记录，不把单测与构建当作视觉通过。本轮不自动提交或发布新版本。

涉及模块：Glance 模型/视图模型/图片服务/设置及内容；SystemMonitorOptions/采样/内容/设置；共享窗口交互的监控专用尺寸接入；现有语言资源。保持功能模块独立，不做范围外重构或依赖升级。

## 4. 代码开发

已完成以下代码；保留工作区已有缓存、文件格子和 Dock 优化改动。

- `GlanceTextContrastPolicy` / `GlanceTextSampleService` / `GlanceWidgetContent.Contrast`：48×48 缩略样本，路径/文件时间缓存，按文字实际区域及图片 Fill/Fit/焦点映射取样；互补 RGB 结合 4.5:1 亮度校验，复杂区域追加局部黑色衬底。仅调整图片上的时间/日期，日历材质中的文字沿用原生主题。高对比度使用系统文字/背景色；图片透明时原生材质无法由图像像素完整表征，采用白字加局部衬底保证清晰。文字尺寸变化、主题、裁剪和图片更新触发防抖更新，每分钟时钟刷新不重复解码。
- `GlanceWidgetData` 版本 11、新增默认开启的 `BingDaily` 和图片 `PublishedDate`；STJ 源生成继续管理配置/目录。当前卡片配置已是 Bing，缺少新字段时自动进入每日模式，不覆盖本地文件列表。
- `GlanceImageService` 每日模式仅请求最新目录、下载新身份；不受历史缓存已满时下载额度为零的影响。已有同身份图片更新发布日期，缓存保留按发布日期优先，失败/离线保留成功文件。`GlanceDailyRefreshPolicy` 按本地日期判断，15 分钟失败重试限频；视图模型启动、显现、跨天/睡眠后时钟检查。来源日期与本地日期分开：成功确认最新目录且最新图片可用时，标记本地当天检查完成，即使 Bing 来源日期是前一天；失败回退不会冒充新目录成功。每日模式停用历史随机计时及下一张按钮，可从设置关闭后恢复历史轮播。
- `SystemMonitorSelection` 默认全开，CPU/GPU/内存/显存/网络分组及 15 项指标设置；关闭项从内容树移除。采样生命周期按选择重建，PDH 只注册所需计数器，NVML 只读取启用传感器；温度/功耗均关时不创建 CPU bridge；网络全关不建立网卡目录，IP 独开不读速率计数。全关停止采样并显示占位；CPU 温度/功耗共用已有 bridge，启用其中一项时仍使用该共享来源。
- `SystemMonitorWidgetContent` 使用统一 Viewbox 缩放，按现有分块自然尺寸计算高度；`SystemMonitorAspectLayout` 与宿主专用约束保持边/角拖拽比例、对侧锚点及屏幕边界。关闭指标后窗口按自然高度收紧，其他内容保留默认无约束路径。
- 新增设置文本同步至现有 12 种语言，补充新控件的无障碍标识。
