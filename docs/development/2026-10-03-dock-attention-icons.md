# Dock 左侧关注区与图标统一

## 调研

当前 Shell 关注事件按窗口 HWND 记录可执行文件路径，激活应用和窗口销毁时清理。Dock 用右侧“!”入口展示列表，固定应用和目录内应用已有关注徽标。图标 Image 布局尺寸一致，但图像自身透明边距不同；共享图标管线只修正明显异常的 Jumbo 图标，正常图片留白仍保留。

使用项目文档先行开发、deskbox-ui-design、windows-native-ui 和界面代码审查规则；已有性能优化方案暂不实施。

## 澄清

按用户本轮要求直接执行：有关注事件的应用显示在 Dock 左端，原生分隔线隔开固定区。同一可执行文件的多个窗口合并一个图标，包含目录内和未固定应用。固定区中的同一应用临时隐藏；事件清理后恢复原磁盘顺序，不修改快捷方式或目录。点击关注图标优先激活请求关注的窗口，不新建应用进程。

关注区临时状态不保存，不等同于应用内部未读数。窗口关闭/激活按现有监听器状态处理；长名称使用 tooltip。达到屏幕宽度上限时关注图标优先分配位置，其余通过更多菜单访问，无主栏滚动条。

只对 Dock 图标做透明留白归一：保持长宽比，使可见主体长边占同一图标槽的约 88%，居中并保留轻量安全留白。不更改原图文件，不影响应用栏/监控图标。完全透明、非法及异常大图片安全回退。

## 规划

1. 独立左侧关注图标容器和主题分隔线；按路径增量同步，复用按钮、图标和当前监听器。
2. 更新宽度、溢出及拖放命中规则，固定项仅临时隐藏；清理后恢复。
3. Dock 专用图标归一工具，解码缓存使用独立变体，原始图标字节保持共享。
4. 快速算法检查、代码审查、Debug 构建与标准路径重启。合成闪烁验证关注增删，实际微信和视觉保持待验收。

## 开发

代码已完成，实机验收待确认。改动限 Dock 和图标解码的可选接入，不启动性能优化报告中的其他任务，不改变现有数据。

- DockWidgetContent.Attention.cs：增量同步关注图标，按路径去重、主题分隔线、窗口激活、固定区临时隐藏恢复与更多入口。
- DockAttentionLayout.cs：关注优先的宽度分配，预留分隔线、命令和外边距，图标不半截裁切。
- DockIconNormalizer.cs：仅内存中的图标按显著 alpha 边界归一，主体长边约 88%，安全回退并释放 GDI/流资源。
- IconHelper：增加默认关闭的可选归一参数，只由 Dock 开启；解码缓存新增专用变体，共享原始字节不改变。
- DockWidgetContent.cs：左关注区/中固定区/右命令区接入；撤下旧右侧“!”列表入口；关注图标保留 DockEntry 命中数据，仍沿用现有拖放路径。

复用既有 Dock.Attention/ClearAttention 文案，无新增产品语言键。Design.md 与项目记忆已同步。
