# 微信关注入口与 Dock 状态提示：开发流程

日期：2026-10-06；阶段：微信关注打开已获用户实机确认，未公开发布。

## 1. 调研报告

用户反馈右侧出现感叹号，微信关注入口不可用。右侧是 `SetStatus` 显示的操作状态按钮，点击浮层显示原因，当前没有鼠标提示。日志中微信 Shell 闪烁事件已到达，关注区已生成；点击激活时 `wechat-tray matching-buttons=0`。问题定位到微信托盘按钮查找而非 Shell 闪烁监听。只读探测复现：主任务栏位于工作区下方，仅边缘两像素可见；微信 Qt 托盘消息窗口仍注册，但 UI Automation 树无 `NotifyItemIcon`，原查找返回 false。原有失败状态在成功切换后也未清除。

2026-10-06 官方资料核对：

10:03 用户复验失败：闪烁事件仍能到达；多次点击均记录 `matching-buttons=0`、前台授权成功、`callback-accepted=True`，但没有微信前台成功记录。消息送达仅说明窗口处理函数返回，不能证明应用执行了恢复。只读回调定位和边界测试未覆盖此实际失败。

继续只读检查本机微信 4.1.15.13：其精确类名包含 `WxTray`，并非上游通用 `Tray`。该注册窗口的类处理函数和后续事件处理函数均比较回调消息 `0x8385`（`WM_APP+901`），而上轮发送的是上游 Qt 的 `0x8065`（`WM_APP+101`）。后者被默认处理后正常返回，却没有进入微信激活分支。这是本轮证实的协议差异；修复限于已经核对的精确类名，不尝试多种回调轮番发送，不读取聊天内容、不修改微信进程代码。

- [微软关于隐藏托盘项的说明](https://devblogs.microsoft.com/oldnewthing/20250929-00/?p=111637/)：隐藏项缺乏可供 UI Automation 操作的 UI。
- [Qt 5.15.2 官方实现](https://github.com/qt/qtbase/blob/v5.15.2/src/plugins/platforms/windows/qwindowssystemtrayicon.cpp)：通用上游实现使用图标 ID 0、回调 `WM_APP+101`；本机 `WxTray` 是微信定制实现，不能据此认定回调号相同。上轮该推断已由本机处理函数证据纠正。
- [Windows 托盘回调结构](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)：版本 4 回调在 lParam 低位携带事件、高位携带图标 ID；坐标位于 wParam。
- [前台授权 API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow)：仅向当前要激活的微信进程授予前台权限。

## 2. 问题澄清

恢复微信当前窗口的关注点击和更新，保留应用自行恢复状态的托盘入口，不退回曾导致消息停留的强制显示隐藏 Qt 窗口方案。说明感叹号的来源，增加可理解的鼠标提示，并在成功操作后清理相应旧失败状态。无需改变用户任务栏、托盘显示配置或安装依赖。当前诊断范围明确，不需要用户再次确认。

## 3. 开发规划

1. 只读探测真实微信托盘注册图标、任务栏与溢出区 UI Automation 的关系，记录脱敏证据。
2. 保留可见按钮的原 UI Automation Invoke，未找到时向唯一、同进程、精确 Qt 类名且经 Shell 确认注册的托盘窗口发送上述激活回调。发送前再次验证身份，限时且不循环发送；原前台验证成功才清理关注。不泛化到其他版本或未知软件。
3. 针对匹配边界添加快速回归测试；构建并重启标准 Debug，真实微信点击另请用户验收。
4. 保留当前无关优化和此前豆包修复；不公开发布。

本轮增补：用本机确认的 `WM_APP+901` 替换错误通用消息号；增加真实注册托盘测试窗口，在隐藏任务栏条件下执行生产路径，断言定制处理函数实际接收到 `NIN_SELECT` 并运行恢复分支。先用旧实现使该测试失败，再修复复验。标准 Debug 重启后真实微信前台和最新消息仍需用户交互验证。

## 4. 代码开发

本轮修正：只读核对本机定制托盘的注册代码，确认写入的 `uCallbackMessage` 也是 `0x8385`，与类处理函数、后续事件分支一致；事件仍为 ID 0 的 `NIN_SELECT`。生产后备现已发送正确消息号，日志明确区分 `delivery-accepted` 与后续前台确认，不把送达作为打开成功。未强制显示隐藏窗口、未改任务栏设置。

新增注册真实托盘项的本地测试夹具，使用对应类名、图标 ID 和定制消息号，在自己的窗口处理函数内记录应用激活。旧生产代码实测 `delivery=True, application-activation=0`（失败），修正后 `delivery=True, application-activation=1`（通过）；测试只操作测试进程自己的托盘项，结束清理。已将该回归加入 `DockWeChatTrayActivationTests`，夹具保存在 `tests/DeskBox.Tests/WeChatTrayCallbackFixture.cs`。为避免再构建整个应用测试依赖，本轮使用本地隔离项目直接编译这份生产源文件及同一份测试，12 项全部通过，测试执行 199ms。

已在 `DockWeChatTrayActivation` 保留可见按钮匹配，并补充经过注册信息和进程/类名二次核对的 Qt 托盘回调后备。不改变任务栏或托盘设置，不启新微信、不强制 ShowWindow；最多发送一次限时回调，后续由原逻辑确认前台归属。`DockAttentionListener` 在用户激活操作中给目标进程前台权限。关注入口、运行入口和正常启动成功后只清理原启动/切换失败状态，其他错误保留；状态按钮增加与无障碍说明相同的鼠标提示。

只读回归先验证原代码返回 false，修复后返回 `callback-available=True (read-only)`；没有发送真实微信激活操作。失败探测初次以未处理异常结束触发错误报告进程，造成探测 EXE 锁定；已仅停止本任务探测进程，改用退出码报告并复验。新增 11 项托盘身份、坐标和原可见按钮边界测试，已与此前 16 项豆包身份测试一并通过。
