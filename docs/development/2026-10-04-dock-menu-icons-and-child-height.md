# Dock 项目菜单、图标资源与主子栏高度

日期：2026-10-04。沿用文档先行、原生 WinUI 设计与根因排查流程。

## 调研报告（已完成）

### OBS 剩余图标反馈

用户后续截图中的 OBS 仍为白纸。只读检查确认：Dock 的 `.lnk` 指向原 `.url`，原 `.url` 再指向 Steam 启动协议并声明图标资源。当前加载器只依据最外层文件扩展名选择 InternetShortcut 路径，因此嵌套 `.url` 未进入已有的 Steam/Shell 图标读取流程。此项属于原任务图标读取的另一种输入，不改启动目标或快捷方式数据。

后续规划：只对 Dock 识别解析后的 `.url`，以其路径进入现有有界 InternetShortcut/Shell 读取和回退流程；保持外层入口启动与显式图标覆盖规则。验证原 `.url` 图标资源存在和可提取、条件接线、Debug 构建及重启；实际显示待用户确认。

后续代码已完成：`GetIconAsync` 在 Dock 模式下将解析后的 `.url` 识别为 InternetShortcut，并使用其路径请求图标；保留外层入口与快捷方式显式图标覆盖。Dock 缓存策略升为 v3。只读探测确认嵌套目标/图标存在，原生图标提取成功，句柄已释放；Debug 构建 0 错误、22 个既有警告，已重启标准 Debug，实际显示未验收。未运行完整测试套件。

- 用户对照中，项目菜单缺少属性、重命名与插入入口。沿用原生 MenuFlyout 补齐必要管理操作，不复制第三方产品的非原生黑色菜单。
- 子栏强制显示名称，并添加标题、12 DIP 内边距、固定图标槽 +88 DIP 高度；主栏默认无名称，图标槽 +16 DIP。因此高度差来自代码，不是 DPI。
- 空白图标样本的快捷方式显式图标存在，文件头为 ICO，但文件没有 `.ico` 扩展名。加载器先向 Shell 请求这个资源文件的「文件类型图标」，得到通用白纸图标后便不再提取实际图标。Dock 应优先提取快捷方式声明的索引资源，再走 Shell 回退。
- 可复用系统属性、文件选择与原子重命名服务；不新增依赖。WinApp CLI 本机不可用，不安装工具或升级依赖。
