# Dock 运行状态、运行项菜单与多屏方案

日期：2026-10-05。前置任务：[运行应用](2026-10-04-dock-running-apps.md)。

## 1. 调研报告（已完成；点击问题仍需交互复验）

- 当前 `EnumWindows` 枚举全部桌面顶层窗口，没有按显示器过滤。实机只读探测识别到 VS Code 一个应用、一个窗口；主栏快捷方式存储目标与进程路径相同。已排除本次机器上的短路径别名假设，不能把此前日志里的其他启动点击直接归因于 VS Code。
- 已固定在主栏的运行应用不会在临时运行区域重复出现。因此缺少临时图标不等于枚举失败。
- 运行圆点采用内容区域之外的负边距；缩放和原生按钮内容布局会使标记缺少实际布局空间。改为明确的内部 4 DIP 状态行，并记录根栏运行匹配数量供复验。
- Dock 当前只有一个配置、一个窗口，自动定位仅使用当前窗口附近的显示器。没有显式屏幕选择，更没有多屏复制。直接复制配置会与功能格子去重、关闭保存和窗口注册逻辑冲突。
- 关闭使用 `WM_CLOSE` 请求窗口正常关闭，允许应用弹出保存提示或拒绝关闭；不是强杀进程。固定到主栏复用已有快捷方式导入、去重、末尾插入和空文件夹清理。

官方资料（2026-10-05 查阅）：[EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows)、[WM_CLOSE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-close)、[MonitorFromWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-monitorfromwindow)。

## 2. 问题澄清（已明确；多屏方案已确认）

- 用户要求：主栏应用正在运行时下方显示圆点，点击激活已有窗口；临时运行项右键可关闭、添加到主栏最右侧。
- 一个应用有多个窗口时保持窗口选择，关闭菜单明确为关闭所有窗口。保存提示交给应用处理。
- 添加到主栏时优先迁移已有子栏快捷方式，保留参数及图标，并复用去重；主栏已有同目标时不添加重复项。不能准确固定的托管应用禁用该操作。
- 多屏默认各屏显示一个 Dock。各屏共享应用、顺序和设置；默认显示全部屏幕的运行窗口，不按所在屏幕隐藏 VS Code。
- 屏幕选择保存 Windows 显示设备名称，界面显示屏幕编号、主屏标记及分辨率。布局变化不覆盖原选择；设备名称不等于永久硬件身份，换接口或驱动重枚举后可能需要重新选择。九宫格定位仍不含中央格。
- 硬件监控保持单张卡片，增加独立屏幕选择，默认主屏右侧居中。

## 3. 开发规划

### A. 本轮直接处理的小范围修改

1. `DockWidgetContent.cs` / `Attention.cs`：为运行点分配真实布局行，主栏比例缩放不裁掉标记。
2. `Running.cs`：运行项菜单增加关闭和固定；固定应用菜单也提供关闭当前运行窗口；加入脱敏匹配计数，点击前必要时更新快照避免陈旧状态。
3. `DockRunningApplications.cs`：按捕获的窗口句柄和进程身份校验后发送非阻塞关闭请求。
4. 字符串：增加中文及英文菜单文本，遵循现有本地化后备规则。
5. 快速原生探测、静态审查，按项目约定停止仓库实例、构建、重启 Debug。用户复验 VS Code 点击、菜单操作。

### B. 多屏改造（2026-10-05 用户已确认，代码已完成）

1. 增加显示方式：所有屏幕（默认）、仅主屏、指定屏幕。Dock 与监控设置复用屏幕选择组件及现有显示器设备识别能力。
2. 一个 Dock 配置管理多个显示窗口；不复制持久配置，不启动多个进程。窗口副本关闭、设置同步和显示隐藏走统一管理，不能覆盖主配置可见状态及其他副本位置。
3. 共用一份运行窗口/通知快照和应用目录数据，避免每块屏幕新增重复扫描；各窗口分别计算 DPI、最大宽度、九宫格位置及子栏边界。
4. 监听显示器接入、断开及工作区变化。指定屏幕断开暂用主屏，保存原设备选择，重连恢复；移除副本时关闭其子栏与菜单。
5. 独立验收双屏复制、屏幕选择、跨屏激活、不同缩放、负坐标、热插拔、重启恢复及运行开销。

恢复方式：保留现有配置和用户快捷方式；A 的固定操作沿用现有本地备份。B 新设置缺省回退，不迁移/删除用户目录。本轮不停止 Nexus、不修改任务栏及启动项、不发布安装包。

## 4. 代码开发（已完成；真实交互验收待确认）

- A：运行圆点改用内部 4 DIP 状态行，按钮不再占用额外描边空间；主栏同比缩放保留状态行高度。点击固定项没有运行匹配时先读取新快照，再决定激活还是启动。
- A：运行项原生菜单增加正常关闭请求、添加到主 Dock 最右侧；已固定项也能关闭运行窗口。固定复用原导入逻辑，优先迁移现有子栏入口保留参数和图标，并避免锁定拖动妨碍显式固定操作。
- B：`WidgetMonitorLayout` 统一显示模式与按目标屏幕 DPI/工作区定位；`MonitorSelector` 提供原生设置控件。入口为「功能格子 → Dock → 位置」，系统监控页提供独立屏幕选择。
- B：`WidgetManager.DockDisplays` 管理临时窗口副本，共享原配置，不复制持久配置；副本使用独立宿主身份，关闭不覆盖主配置可见状态。显示拓扑变化时重算目标，暂缺指定设备回退主屏但保留偏好。
- B：`DockRuntimeSession` 共享 Shell 监听器、目录监听/缓存和后台窗口快照；重用正在进行的扫描，多屏不各自启动独立传感器或进程。设置与顺序变化通知各视图，目录 COM 读取在后台执行且不占用快照锁。
- 已补充 `WidgetMonitorLayoutTests`。保留其他未提交修改，未升级依赖。WinApp CLI 未安装，本轮未进行该工具的 API 查询，不自动安装。
