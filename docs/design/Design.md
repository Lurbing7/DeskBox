## 1. 产品与视觉定位

**强制要求：整体呈现 Windows 系统原生质感。** 所有现有及新增卡片（包括性能监控）遵守 [Windows 原生 UI 基线](windows-native-baseline.md)。微软官方规范、WinUI 原生控件及实机系统界面对照优先于本文的历史参数和 HTML 试验；现有源码仅说明现状，不自动代表合格设计。

当前执行优先级和验收进度维护于 [项目记忆与执行清单](../../PROJECT_MEMORY.md)：先验证性能监控可行性并完成卡片，最后统一包括监控在内的整体原生 UI；原生质感仍是最终验收硬要求。

DeskBox 是附着在 Windows 桌面上的工具卡片。界面由桌面格子、胶囊、格子组、搜索窗口、设置窗口和临时浮出面板组成。主要操作直接发生在内容区；复杂偏好进入设置；临时操作使用菜单、浮出面板或就地编辑。

视觉保持 Windows 原生 Fluent 语言：主题资源、真实软件图标、轻量材质、低对比度分隔、克制的悬停反馈。内容是视觉中心，装饰不应压缩图标与名称的可读空间。

已有页面参考：[文件格子](../images/screenshots/zh-cn/文件格子.png)、[外观设置](../images/screenshots/zh-cn/外观.png)、[功能格子](../images/screenshots/zh-cn/功能格子.png)、[胶囊模式](../images/screenshots/zh-cn/胶囊模式.png)。这些图片可能来自旧版本，具体数值以当前源码为准。设计文档与技能不收录个人桌面截图或个人应用清单。

## 2. 三类界面结构

| 界面 | 结构与用途 | 现有入口 |
|---|---|---|
| 桌面格子 | 标题壳 + 内容区；支持移动、边框缩放、临时唤起和胶囊 | `ContentWidgetWindow`、`WidgetShell` |
| 设置窗口 | 左侧导航 + 内容页；统一设置行和分组卡片 | `SettingsWindow`、`Views/SettingsSections` |
| 临时浮出面板 | 菜单、数值设置、颜色选择与确认；交互结束后释放临时层级 | `MenuFlyout`、`Flyout`、宿主交互方法 |

新格子优先使用 `IWidgetContent` 和内容 provider，交给共享宿主处理标题、材质、窗口尺寸、层级和生命周期。当前随记实际内容路径为 `QuickCaptureSurfaceContent`；历史独立窗口仍有源码和契约测试，不代表新功能应使用该宿主。

### 基础参数

### 明暗主题基础色

| 资源 | 浅色 | 深色 |
|---|---|---|
| `WidgetBackgroundBrush` | `#F3F3F3` | `#1F1F1F` |
| `WidgetTextBrush` | `#1A1A1A` | `#F5F5F5` |
| `WidgetTextSecondaryBrush` | `#5A5A5A` | `#A5A5A5` |
| `WidgetDividerBrush` | `#D0D0D0` | `#3C3C3C` |
| `WidgetOverlaySurfaceBrush` | `#FBFCFD` | `#2A3038` |
| `WidgetOverlayInputSurfaceBrush` | `#FFFFFF` | `#222830` |
| `WidgetOverlayStrokeBrush` | `#24000000` | `#52FFFFFF` |

悬停、按压、打开状态使用现有 `WidgetTitleState*Brush` 或中性交互画刷。危险操作使用已有危险操作样式；普通选择与悬停不应使用错误色。

## 4. 材质、边框与外轮廓

卡片使用应用支持的云母、亚克力或纯色策略。最终透明度与材质强度由 [WidgetMaterialVisualCalculator](../../src/DeskBox/Services/WidgetMaterialVisualCalculator.cs) 和宿主处理，新内容区保持透明或使用已有层次画刷，避免再绘制一个不透明背景盖住材质。

外部圆角、阴影、边框属于窗口层；内部控件圆角属于 XAML 组件层。例如 `WidgetShell` 的背景板声明 `CornerRadius="0"`，不能据此认定运行卡片是直角。Windows 版本和 DWM 圆角偏好均影响最终轮廓。

保持明暗主题、格子独立配色、普通材质回退和高对比度下的可读性。图片或壁纸颜色变化后，正文仍须清晰。

## 5. 标题栏

来源：[WidgetShell.xaml](../../src/DeskBox/Controls/WidgetShell.xaml)、[WidgetTitleBarMetrics](../../src/DeskBox/Services/WidgetTitleBarMetrics.cs)。

- 标准结构：左侧类型图标与标题，右侧添加和更多按钮；是否显示由内容能力与用户设置决定。
- 标准外边距为 `14,4,12,4`；紧凑标题为 `12,2,10,2`。
- `WidgetShell` 初始标题行最小高度为 40；运行时由标题指标计算覆盖。计算中的最小内容高度为 32，不能将“32”当作所有标题栏的总高度。
- 标准模式图标计算范围为 11–18，标题文字为 12–18，按钮为 24–34；紧凑模式图标为 10–15，按钮为 22–28。实际值取决于设置。
- 图标和标题之间的初始间距为 8。标题超长时省略，编辑保留完整名称。
- 标题拖拽、就地改名和菜单操作保留宿主已有交互语义。新内容不要覆盖整个标题栏来加入业务导航。

分类导航、任务过滤等业务控件放在内容区，和“格子组标题导航”区分；两者管理不同的对象。

## 6. 文件与应用图标网格

来源：[FileWidgetIconLayout](../../src/DeskBox/Services/FileWidgetIconLayout.cs)、[FileSurfaceContent](../../src/DeskBox/Controls/WidgetContents/FileSurfaceContent.xaml)、[FileWidgetGridSettings](../../src/DeskBox/Services/FileWidgetGridSettings.cs)。

单元格同时考虑图标大小、文字大小、文件名宽度、行数、横纵间距和系统文字缩放。名称位于图标下方，可单行、双行或隐藏。固定文件名宽度不是单元格的唯一决定因素。

```text
单元格宽 = ceil(图块宽 + 左右 margin)
单元格高 = ceil(图块高 + 上下 margin)
物理像素对齐后的尺寸 = ceil(单元格尺寸 × DPI缩放) / DPI缩放
```

当前文件内容外边距是 `9,4,9,8`。尺寸计算需加上标题、导航和宿主占用的真实高度，不使用截图中估算的固定总高度。

本 fork 已加入的设置：

| 设置 | 当前行为 |
|---|---|
| 列数 × 可见行数 | 每项 1–30；新建普通文件格子默认 4×4；支持 2×10 |
| 水平对齐 | 默认整组列居中，可选靠左；末行沿用完整列网格对齐 |
| 拖拽吸附 | 默认开启；调整大小结束后吸附到完整行列；可关闭 |
| 右上角定位 | 按屏幕工作区定位，记录右上角锚点和边距 |
| 内容溢出 | 超过可见行数可滚动；窗口不因目标行数越出屏幕工作区 |

设置入口是格子标题“更多”→“网格尺寸与对齐”。存储在格子 `Metadata`，并非新增全局外观字段。已有格子不会在普通启动时全部强制变成 4×4。2×10 表示 2 列应用、10 行可见内容，不是最大 20 个应用。

居中均分不足一列的剩余宽度；它不消除有意保留的空白行。卡片增加侧栏后，行列尺寸应只描述应用区域，侧栏必须另计宽度。

## 7. 选择、启动与反馈

文件格子保留现有 Windows 操作习惯：选择和启动分开，支持 Ctrl/Shift 多选、框选、键盘导航、右键菜单、文件拖放和重命名。具体启动行为沿用现有设置与 `FileService` 路径。

图标名称的 `AutomationProperties`、焦点状态、悬停、按压和选择状态均应可辨识。新应用卡片的分类选择与应用选择使用两套状态；切换分类时不能把焦点送到隐藏项目。

反馈位置与任务范围一致：单项失败就近反馈，批量操作给出汇总及失败目标。空状态提供说明和一个明确入口；加载状态不能遮住仍可操作的已有内容。

小格子内的 `ContentDialog` 会受窗口空间约束而裁切，已有源码对此有明确说明。小型数值编辑和轻量确认优先沿用宿主的 `Flyout` 与交互租约。需要大量内容的管理界面进入设置页，不能直接把设置窗口的 800 宽约束搬进卡片。

## 10. 动效与资源生命周期

采用共享动画节奏表达悬停、菜单、内容切换与窗口状态。具体动画仍由现有控制器和设置决定，83/167/250ms 不是对每个窗口动作强制统一的常量。

连续动画服从性能设置；隐藏、长时间隐藏、胶囊状态和停用功能应按 `IWidgetContent` 及已有生命周期释放或暂停资源。分类切换不应重建外部窗口、重新扫描整盘，或为同一个应用在每个标签下重复解码大图标。

## 11. 性能监控与功能边界

性能监控卡片保留，指标来源、字体层级、动态图标及未验证项见 [开发记录](../development/2026-10-02-system-monitor.md)。标签分类已于 2026-10-03 按用户要求撤下，不再提供分类卡片和设置入口；文件卡片网格尺寸及对齐保持可用。

## 12. 设计验收与维护

### Dock 关注区与图标规则（2026-10-03）

2026-10-05 方向与边缘规则：位置 4/6 的主 Dock 纵向排列，原横向最左项位于最下面，通知区在底部并使用横向分隔线；其余位置横向。存储顺序保持不变，纵向上下拖放转换为原序列插入位置。主栏按当前主轴（纵向为高度）同比缩小全部图标，保留运行状态行，禁止滚动隐藏。1/3/7/9 按完整窗口对应的两条边缘定位，按目标屏幕 DPI 和工作区钳制；子栏仍横排，侧边主栏优先向屏幕内侧展开，角落子栏沿相应边缘对齐。规则与未验证交互见 [开发记录](../development/2026-10-05-dock-orientation-and-edges.md)。

2026-10-04 运行应用规则：设置 → 功能格子 → Dock → 内容，提供「显示正在运行的程序」，默认开启。有顶层窗口的运行应用（含最小化）按可执行路径合并；没有主栏固定入口的应用显示在右侧临时运行区，使用同规格主题分隔线。主栏已有应用显示底部 4 DIP 主题色运行圆点，点击直接切换现有窗口，多窗口展示原生选择菜单；未运行时启动。圆点位于缩放 Viewbox 外，底部空间保留，避免满宽缩小时状态点过小；Dock 窗口高度不增加。子栏快捷方式仍普通启动。临时项单窗口点击激活、多窗口展示原生窗口菜单，不重复启动、不写入目录。文件夹中的入口保持原位，临时运行区仍提供入口；左侧通知优先保留，避免重复临时项。三个区域共同按最大宽度同比缩放，子栏运行圆点沿用相同状态。默认开关关闭即停止运行扫描并恢复普通启动；只驻留托盘且没有可见窗口的程序不在该区域。见 [开发记录](../development/2026-10-04-dock-running-apps.md)。

2026-10-04 设置入口更新：设置 → 功能格子 → Dock，以及主/子栏项目菜单与主栏空白菜单中的「Dock 设置」，使用同一原生设置页并按实例定位。设置按内容、位置、外观、行为、子 Dock、维护分组，可独立恢复默认；缺失值沿用当前行为。图标间距默认 2 DIP（0–12），屏幕边距默认 12 DIP（0–64），拖放停留展开默认 600 ms（200–1500），普通滚轮每格默认 3 项（1–6）；图标拖动锁定和普通悬停展开默认关闭。位置锁定复用宿主设置；主栏缩放与子栏宽度同步使用配置间距，触控板仍使用原生平移。布局浮出设置入口已归并，自动隐藏尚未实施。见 [设置扩展记录](../development/2026-10-04-dock-settings-roadmap.md)。

2026-10-04 满宽规则更新：主栏全部固定项和关注项始终可见，达到最大宽度时同比缩放图标内容、按钮命中范围及间距，减少项目后恢复配置基准大小；主栏不滚动、不隐藏尾项。子栏保留基准图标大小和横向滚动，普通滚轮无需 Shift；水平滚轮及触控板平移保留原生处理。窗口高度继续统一。此规则替代旧的主栏容量隐藏与更多入口承载溢出描述；更多按钮仍为独立可选命令入口。见 [开发记录](../development/2026-10-04-dock-fit-and-child-scroll.md)。

2026-10-04 主子栏一致性：主栏与子栏共享图标槽、左右 8 DIP、上下 8 DIP 及名称开关，默认高度 64 DIP（40 DIP 图标），开启名称为 84 DIP。子栏不强制标题和名称行，文件夹名称仍叠在图标内；横向溢出保留滚动。项目菜单使用原生 MenuFlyout，提供打开、资源管理器显示、重命名、插入、移除、系统属性及布局设置；外部目录子项仅提供读取操作。显式图标资源按索引提取，不能把无扩展名 ICO 的文件类型图标当成应用图标。见 [开发记录](../development/2026-10-04-dock-menu-icons-and-child-height.md)。

2026-10-04 紧凑间距：保留图标本体 32/40/48 DIP，按钮槽为图标大小加 8 DIP，项间距 2 DIP，主栏左右各 8 DIP。更多按钮默认关闭，在「Dock 布局设置」启用；空白右键始终提供「全部 Dock 项目」。图标和文件夹使用独立原生菜单，自有入口可「从 Dock 移除」，备份保留；通知入口只能清除提醒，外部链接的子项不提供移除。子 Dock 菜单交互期间暂停外部点击收起。见 [开发记录](../development/2026-10-04-dock-density-and-item-menu.md)。
